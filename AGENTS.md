# AGENTS.md — AI Agent Contribution Guidelines

This document defines the strict rules, conventions, and constraints for **AI Agents** (and AI-assisted human developers) contributing code, documentation, or refactoring to the **NexusAI** repository.

---

## 📜 Core Directives for AI Agents

1. **Do Not Over-Write or Fabricate Documentation**
   - Never invent fictional benchmarks, fake metrics, or unverified performance claims.
   - Always state *Target*, *Current Status*, and *Measurement Methodology*.

2. **Definition of Done (DoD)**
   Every PR or code change generated by an AI Agent **MUST** satisfy:
   - ✅ All unit tests pass (`pytest`).
   - ✅ Static analysis passes (`ruff check`, `black --check`, `mypy --strict`).
   - ✅ `CHANGELOG.md` is updated if changes are user-facing.
   - ✅ Relevant documentation under `docs/` is updated.
   - ✅ An ADR (`docs/adr/`) is created if core architecture changes.

3. **No Unsanctioned Architectural Refactoring**
   - AI Agents must NOT perform large-scale refactoring across core boundaries (`bus/`, `brain/`, `security/`) without an approved RFC under `rfcs/`.

4. **Preserve Public API Contracts**
   - Do NOT break existing method signatures, Pydantic schemas, or CLI parameters without adding deprecation warnings and updating corresponding tests and specifications (`docs/specs/`).

---

## 🐍 Python Coding Standards for AI

- **Python Version**: Target Python 3.12+ features (e.g., modern type syntax `X | Y`, `type` alias statement).
- **Type Annotations**: All functions and methods MUST have explicit type annotations for parameters and return values (`mypy --strict` compliant).
- **Docstrings**: Google-style docstrings for all public classes and functions.
- **Error Handling**: Custom exceptions inheriting from `NexusAIError` in `nexusai.core.errors`. Never swallow exceptions silently.
- **Logging**: Use `loguru` (`from nexusai.logging.logger import logger`). Never use `print()`.

---

## 📝 Commit Conventions

AI Agents must use [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` New feature
- `fix:` Bug fix
- `docs:` Documentation changes
- `style:` Formatting or lint fixes
- `refactor:` Code change that neither fixes a bug nor adds a feature
- `test:` Adding or updating tests
- `chore:` Maintenance tasks

---

## 🛡️ Security & Secrets Constraint

- **NEVER** embed hardcoded API keys, secrets, tokens, or dummy keys containing `key-` string patterns in source files or tests.
- Always retrieve credentials dynamically from environment variables (`os.getenv(...)`).
